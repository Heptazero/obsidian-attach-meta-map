# Att Meta Map — Obsidian 附件配套笔记与整理

[English](./README.md)

Att Meta Map 是一个 **Obsidian 插件，用于给 PDF 等附件创建 Markdown 配套笔记、从文件和 PDF 元数据填写笔记属性，以及按文件夹和命名规则整理附件**。适用于文档库、同时保存原文和译本的论文资料，以及需要通过笔记属性筛选的附件。

可以用 **Sidecar** 将附件保留原位，只创建配套笔记；也可以用 **Folder** 将附件和笔记收进同一个条目文件夹。笔记的 `source` 属性明确记录对应文件，一篇笔记可以关联多个资源，不限于一个 PDF。

[安装](#安装) · [快速开始](#快速开始) · [常见问题](#常见问题) · [自动触发和安全边界](#自动触发和安全边界)

## 你想解决什么问题？

| 你可能会问 | Att Meta Map 提供的做法 |
|---|---|
| Obsidian 能不能给每个 PDF 自动创建一篇 Markdown 笔记？ | [映射组](#选择-sidecar-或-folder-布局)可以为新出现的匹配附件建配套笔记；已有文件通过批量补齐预览处理。 |
| 能把 PDF 的标题、作者、页数填进笔记属性吗？ | [模板与元数据映射](#让模板控制元数据)支持文件和 PDF 元数据，以及可选 DOI/ISBN 查询，不生成论文摘要。 |
| 英文原文、中文译本和幻灯片能不能共用一篇笔记？ | [`source` 双链列表](#只保留一种明确关系)可关联多个文件；Folder 组支持按配置的附属前缀归入已有条目，但不会翻译文件。 |
| 怎么并排打开附件和笔记，查看、解除它们的绑定？ | 「成对打开」显示两侧文件；「资源关系」面板列出、打开和解绑 `source`，解绑不删文件。见[命令](#命令和文件菜单)。 |
| 能一份资料一个文件夹，也能保留 PDF 原来的位置吗？ | [Folder 和 Sidecar](#布局细节) 分别支持这两种方式；Folder 可选层级，也可以只整理文件、不建笔记。 |
| 能监听文档文件夹里的所有格式，不逐个填写后缀吗？ | 使用[黑名单](#只监听指定后缀或处理全部附件)并清空排除项；Markdown 始终排除，不支持直接输入 `*`。 |
| 能按后缀、来源文件夹和优先级移动附件、重命名和重排序号吗？ | [有序附件规则](#用有序规则整理组外附件)支持包含、排除条件及连续编号；仅手动执行、先预览，且只处理映射组根目录之外的文件。 |
| 删除 PDF 后能删对应笔记，删除笔记后也能删附件吗？ | [可选 source 联动删除](#自动触发和安全边界)支持两个方向并保护共享资源；插件两个方向默认关闭，Obsidian 原生清理另行处理。 |

**启用自动处理前：** Folder 会移动匹配文件，Sidecar 不移动资源。映射组自动事件不会弹出批量确认。先用小型测试文件夹验证，并阅读[安全边界](#自动触发和安全边界)，尤其是同步工具或其他附件插件也会改动文件时。

Fork 自 [Attachments Library](https://github.com/compadrejunior/attachments-library)（José Compadre Junior，MIT）。

## 功能

### 只保留一种明确关系

每篇受管理的笔记都有固定的 `source` 属性，值可以是一个双链，也可以是双链列表。只有它能决定哪些资源属于这篇笔记。

- 同名、同目录和相同文件尺寸都不会自行形成已有关系。
- 一篇笔记可以同时关联原始 PDF、译本、幻灯片、数据或其他附属资料。
- 从笔记或任意已关联资源执行“成对打开”，都会在左侧打开资源，并在右侧复用同一个笔记标签页。
- “资源关系”侧栏逐项列出 `source`，可以打开或明确解绑。解绑永远不会删除文件。

### 选择 sidecar 或 folder 布局

- **Sidecar**：资源和笔记分别位于两个根目录。资源原地不动，笔记可以镜像资源的子文件夹结构。
- **Folder**：只使用一个集合根目录，并选择附件所在层级。根目录直接文件是 `0` 级，下一层是 `1` 级，依此类推。「包含更深子级」可将范围扩展到所有更深层级，默认关闭。

在设置的待整理附件层级，散落资源会移入对应条目文件夹，并在启用时创建笔记。当前父目录已经匹配条目名时，复用该文件夹，只补建笔记。已有 `source` 关系不会再次折叠。

Folder 组可以配置多个附属文件前缀，例如 `cn_`、`zh_`、`slides_`。去掉前缀后与已有条目同名的文件会加入那个条目文件夹，并追加到笔记的 `source` 列表。

### 只监听指定后缀或处理全部附件

在「设置 → Att Meta Map → 对应映射组 → 路径与文件 → 后缀筛选方式」中选择：

- **白名单**（默认）：只处理列出的后缀，例如 `.pdf, .epub`；留空不处理。
- **黑名单**：处理未被排除的附件；留空时，在该组文件夹和层级范围内处理全部附件，也包含无后缀文件。文档文件夹无需维护长串后缀列表，不支持直接输入 `*`。

初始黑名单是 `.md, .canvas, .base`，Canvas 和 Base 可以移除。Markdown 始终排除，即使移出黑名单或加入白名单也不处理，避免自动生成「笔记的笔记」。

两份列表独立保存，切换时恢复各自内容。原 `watchedExtensions` 字段继续保存白名单，已有组行为不变。右键、批量、自动监听共用筛选及原有层级规则；已有 `source` 关系仍可打开，不受后缀筛选影响。见[筛选实现](./src/extension-filter.ts)和[测试](./tests/extension-filter.test.ts)。

### 让模板控制元数据

每组选择一篇 Markdown 模板。模板 frontmatter 的键就是这组笔记的字段白名单；全局映射表决定每个键可以从哪里取得值。

可用来源包括：

- 库和文件：路径、名称、后缀、大小、日期，以及从文件名解析出的年份和标题
- PDF 元数据：标题、作者、主题、关键词、日期、creator、producer 和页数
- 可选联网查询：DOI 或 ISBN、标题、作者和年份

多个来源可以映射到同一属性。目录顺序中第一个非空值胜出，因此已有文件名或 PDF 元数据不会被后面的联网结果覆盖。重新抽取时会并排显示当前值和新值，只写入明确选中的行。

### 用有序规则整理组外附件

附件规则只处理所有映射组资源根目录之外的文件，可以移动并重命名附件。

- 规则从上到下执行，第一条命中后停止。
- 同一栏多个值是“或”，不同栏是“且”，排除栏是“非”，留空表示不限。
- 原始文件夹和后缀都能从当前库中模糊选择。
- 命名支持 `{{basename}}`、`{{parent}}`、`{{note}}` 和 `{{index}}`。
- `{{index}}` 每次根据完整目标快照取最小可用正整数，因此现有 `1、82` 可以重排成 `1、2`。

映射组资源根目录是硬保护区，通用规则永远不会触碰已经属于某组的文件。规则目前只手动运行，而且确认前一定展示完整变化树。

例如，将 `Inbox/Papers` 的 PDF 专用规则放在最前，把更宽泛的兜底规则放在最后；一个文件只执行第一条命中规则，而不是执行全部命中规则。条件使用独立的包含、排除输入栏，不需要脚本语言。见[规则规划器](./src/attachment-rules.ts)。

## 安装

### Obsidian 社区插件

Att Meta Map 通过 Obsidian 社区目录审核后，可以从“设置 → 第三方插件 → 浏览”直接安装。

### BRAT 或手动安装

审核完成前，可以在 [BRAT](https://obsidian.md/plugins?id=obsidian42-brat) 中添加 `Heptazero/obsidian-attach-meta-map`，或从[最新 Release](https://github.com/Heptazero/obsidian-attach-meta-map/releases/latest)下载 `main.js`、`manifest.json`、`styles.css`，放入：

```text
<vault>/.obsidian/plugins/att-meta-map/
```

然后重新加载 Obsidian，并在“第三方插件”里启用 **Att Meta Map**。

## 快速开始

1. 打开“设置 → Att Meta Map”，选择中文、English 或“跟随 Obsidian”。
2. 新建映射组，选择 **Sidecar** 或 **Folder**。
3. 设置资源文件夹、模板、监听后缀和创建行为。
4. 右键一个资源，执行“成对打开”。如果还没有笔记，插件会按该组规则创建相应笔记或文件夹。
5. 大批量补齐前检查完整的红绿文件夹树，只有每个目标都正确时才确认。

## 关系模型

模型有三条规则：

1. **`source` 是固定关系字段**，不属于可配置元数据映射。
2. **模板决定有哪些元数据字段**。往模板 frontmatter 增加一个键，就等于为这一组启用该字段。
3. **全局映射决定值从哪里来**。即使配置了“PDF 作者 → author”，模板里没有 `author` 时也不会写入。

因此模板本身就是字段开关。Att Meta Map 始终维护 `source`；其他属性必须同时得到模板和映射表认可。

例如，一篇论文笔记可以关联三个已有文件：

```yaml
---
source:
  - "[[paper.pdf]]"
  - "[[cn_paper.pdf]]"
  - "[[paper-slides.pptx]]"
---
```

无论资源放在一起还是分开存放，都由这些链接定义关系；普通正文链接和反链不建立这项绑定。添加多项 `source` 不会翻译、复制或合并文件。见[source 链接解析](./src/resource-links.ts)。

## 布局细节

### Sidecar

Sidecar 组分别配置资源根目录和笔记根目录。映射功能永远不会移动资源；笔记可以镜像资源子目录，也可以保持扁平。

### Folder

Folder 组配置一个集合根目录、待整理附件层级，以及可选的「包含更深子级」。

- 在设置的层级创建或复用条目文件夹，需要时搬入附件，并按设置决定是否创建笔记。
- 当前父目录匹配条目名时直接复用；配置层级下一层的匹配条目文件夹也可补建缺失笔记。
- 关闭「包含更深子级」时保持精确层级；开启后处理所选层级及所有更深子级。例如选 `1` 级时处理 `1、2、3……`，不处理更浅的 `0` 级。
- 更深层级保留原分类目录，在附件当前位置建立或复用条目文件夹；已有 source 绑定的条目跳过，匹配的嵌套组仍优先。
- 已有 `source` 关系后，文件夹可以自由改名，因为目录名称不定义绑定。

如果只要文件夹整理，不需要索引笔记，可以关闭“为新附件建笔记”。设置的层级仍会创建或复用条目文件夹，但该组不再运行模板、元数据抽取和笔记维护。

## 模板和映射

Att Meta Map 会自动发现 Templater 的 `templates_folder` 和核心 Templates 插件目录，设置里还可以添加额外模板文件夹。

模板正文会复制到新笔记。`type: paper`、`status: active` 等模板自带值原样保留。Templater 的 `<% ... %>` 块不会执行，而是被移除，因为 `tp.file.move()` 一类命令可能把新笔记移出映射边界。需要动态行为时，可以创建后手动运行 Templater。

没有选择模板时，插件使用内置最小字段：`source`、`title`、`author`、`created`、`updated`，并省略空值。

笔记名和链接模板支持：

- `{{basename}}`、`{{name}}`、`{{ext}}`、`{{path}}`、`{{folder}}`
- 从常见“作者 - 年份 - 标题”文件名解析的 `{{year}}` 和 `{{title}}`

如果笔记名模板要求 `{{year}}`，但文件名没有年份，整个模板会退回安全文件名，不生成残缺名称。插件也会自动修正有歧义的无后缀链接，避免 `[[paper]]` 指向 `paper.md` 而不是 `paper.pdf`。

## 命令和文件菜单

| 命令 | 作用 |
|---|---|
| 成对打开 | 左侧打开资源，右侧复用一个笔记标签；允许时创建缺失笔记 |
| 重新抽取元数据 | 并排显示当前值和抽取值，只应用选中的行 |
| 解绑当前资源 | 确认后移除选中的 `source`，不移动或删除文件 |
| 打开资源关系面板 | 在侧栏列出当前笔记或资源的全部 `source` |
| 补齐缺失的笔记 | 扫描所有组，完整预览移动、建笔记和写入 `source` 后再执行 |
| 按规则整理当前笔记的附件 | 对活动笔记链接的组外附件应用通用规则 |

文件菜单还可以整理当前笔记的附件、单个附件、一个文件夹或递归文件夹。所有入口共用同一套规划器、预览和受保护执行器。

整理和补建预览里，红色 `−` 表示文件将离开旧路径，不代表删除；绿色 `+` 表示新路径、新笔记或 `source` 值将出现。取消这些预览时零写入。联动删除使用独立预览，红色表示将剩余文件移入废纸篓，或移除一项 `source`。

## 自动触发和安全边界

插件启用期间，映射组常驻监听 `create`、`rename` 和 `modify`。脚本、同步工具和 Git 带来的文件变化，也可能触发与 Obsidian 内操作相同的事件。通用附件规则不注册自动监听。

在「常规 → 联动删除」中可启用双向联动。插件自己的两个方向默认关闭，变化确认默认开启。资源→笔记方向关闭时，资源消失后，笔记及其 `source` 断链保留。

Obsidian 1.12 及以上版本中，如果「文件与链接 → 删除文件时删除附件」为「每次询问」（Obsidian 默认值）或「始终」，笔记→资源这一项显示开启并置灰，小字注明由 Obsidian 原生处理。插件跳过此方向，避免两个确认窗口同时出现。原生清理遵循 Obsidian 的链接规则与确认设置，插件的预览开关不控制它。原生设为「从不」后，插件的 source 专属选项恢复可操作，并恢复此前保存的开关值。旧版 Obsidian 中仍可使用插件选项。

检测使用当前库实际的配置目录，打开设置时及每两秒刷新，并在插件删除前复查。不修改原生设置。暂时无法读取原生配置时，此方向暂停，检测恢复后继续。

- **资源 → 笔记**：删除最后一个 `source` 资源后，将对应笔记移入废纸篓。有其他 `source`（包括尚未解析的双链）时，只移除被删资源的那一项。
- **笔记 → 资源**：删除受管理的笔记后，将已解析的 `source` 资源移入废纸篓。其他笔记仍通过 `source` 引用的资源保留；Markdown 和 Canvas 目标不参与联动删除。
- **变化确认**：文件树展示后续变化。第一个文件已由 Obsidian 删除；取消保留另一边的文件及属性，不会恢复第一个文件。关闭确认后按相同规则自动执行。

只有位于启用笔记创建的映射组笔记根目录内的笔记参与联动。资源可以在任意位置，但必须在尚存在时解析过 `source` 关系。关系索引只保留在当前会话，不按名字猜绑定，也不在启动时清理旧孤立笔记。监听单个文件删除事件，文件夹事件本身不递归联动；同步、脚本和 Git 也可能触发文件删除，因此仅在需要此行为时开启。

插件通过 Obsidian 废纸篓接口删除文件，遵循库内 `.trash` 或系统废纸篓偏好，不会退回永久删除。确认窗口按队列逐个展示；恢复第一个文件、修改候选文件或其关系、关闭方向开关或卸载插件，都会停止待执行操作。插件自己的删除不会继续触发联动。失败时停止并提示，已经执行的文件仍在废纸篓中。

其他边界：

- 只写模板和映射表共同认可的属性。
- 修改时间同步只更新笔记已经存在的属性。
- 目标笔记名被占用时退回带扩展名的名字，绝不覆盖已有文件。
- 批量移动使用执行前快照和临时名。预览后状态变化时整批拒绝；移动失败时尝试恢复原路径。
- Folder 遵循设置的层级范围，仅在开启时包含更深子级，并标记插件自己的移动，避免 rename 监听再次处理。

外部修改 `data.json` 后，正在运行的插件不会立刻重新加载。请禁用再启用插件、执行“View → Force Reload”，或重启 Obsidian。

## 常见问题

### 它能把 PDF 转成 Markdown、翻译论文或导出批注吗？

不能。配套笔记是链接到附件的 Markdown 文件，不是 PDF 正文的转换结果。Att Meta Map 读取 PDF 元数据，并可通过检测到的 DOI/ISBN 查询书目信息；不提供 OCR、全文转换、翻译、批注提取、引用数或 AI 摘要。这些任务需要其他工具，已有输出文件可按需通过 `source` 关联。

### 只能处理 PDF，还是也能管理 EPUB、图片和幻灯片？

映射组可为后缀筛选允许的非 Markdown 文件创建配套笔记，包括 EPUB、图片和幻灯片。它们可以使用通用文件元数据；内嵌标题、作者、页数的提取仅针对 PDF。关联文件不会为其格式增加新的阅读器。

### 能替代 Attachment Management 一类附件管理插件吗？

如果需要手动按规则移动、重命名映射组之外的附件，Att Meta Map 已包含这部分能力，但不是所有附件管理插件的完整替代。通用规则不会拦截粘贴或拖入事件，不覆盖 Obsidian 的附件存放位置设置，也不自动运行；映射组创建有自己的自动监听。不要让多个插件同时负责同一批文件的搬移。

### 需要 AI 服务、账号或联网吗？

不需要 AI 服务或账号。创建配套笔记、本地 PDF 元数据提取、关系管理和附件整理都在本地进行。可选的 DOI/ISBN 查询需要连接 Crossref/Open Library，默认关闭。

## 隐私、语言和架构

- 笔记、附件、设置和抽取出的 PDF 元数据都保留在 Obsidian 库内。
- DOI/ISBN 查询默认关闭。启用后，检测到的 DOI 会发送给 Crossref，ISBN 会发送给 Open Library，以获取书目信息。
- Att Meta Map 不需要账号，没有遥测、广告，也不访问库外文件。

界面可以跟随 Obsidian，也可以直接切换中文或 English。翻译按消息键集中保存在 `src/i18n/locales/en.json` 和 `src/i18n/locales/zh.json`，界面代码没有散落的中英文副本。

实现把确定性规则与 Obsidian 文件写入分开：

- `settings-model.ts` 负责默认值和持久设置规范化。
- `sources.ts` 解析元数据，`metadata-types.ts` 保存共享数据模型。
- `metadata-diff.ts` 定义刷新和安全补值规则，不依赖任何弹窗。
- `paths.ts` 负责确定性的目录、命名和链接策略。
- `creation-plan.ts` 定义可预览的笔记和文件夹变化。
- `attachment-rules.ts` 规划通用附件移动，`attachment-organizer.ts` 执行已确认计划。
- `note-manager.ts` 是面向 Obsidian 的服务，负责解析关系和执行受保护的笔记操作。
- `deletion-policy.ts` 从 source 快照规划联动；`deletion-manager.ts` 维护会话索引并执行受保护的废纸篓和属性操作；`deletion-modal.ts` 展示确认树。

## 开发

```bash
npm install
npm run pipeline
```

流水线依次运行 Obsidian lint、带覆盖率的单元测试、TypeScript 检查和生产构建。Obsidian Release 包含 `main.js`、`manifest.json`、`styles.css`。

问题和贡献请提交到 [GitHub 仓库](https://github.com/Heptazero/obsidian-attach-meta-map)。
